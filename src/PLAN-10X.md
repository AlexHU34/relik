# PLAN-10X — как сделать Relik в десятки раз лучше

Дата: 30.10.2026. База: `v1.26.0`.
Ответы владельца: 5–20 знакомых, 10–20 ч/нед, ~$20–50/мес, публичный продукт — в будущем, критерий успеха — **числа**.
Приоритеты: **скорость разработки → надёжность доставки → безопасность → производительность/UX → масштаб → продукт**
(масштаб и рост сознательно стоят последними: они бессмысленны, пока первые четыре не в норме).

## 2. «Как пятилетнему»: что такое build-шаг, TypeScript и почему НЕ React

Представь, что код — это конструктор.

- **Сейчас** ты хранишь его в одной огромной коробке. Чтобы достать деталь, вываливаешь всё на пол. Работает, но каждый раз долго и можно что-то раздавить.
- **Разбиение файлов** — это ящики с подписями: «сообщения», «настройки», «звонки». Достаёшь нужное, не вываливая всё.
- **TypeScript** — это наклейки на деталях: «это винтик, а не шестерёнка». Если пытаешься вставить не то — тебе говорят **до** того, как всё сломалось. Работает как проверка орфографии, только для кода.
- **Сборщик (Vite)** — это упаковщик. Он берёт все ящики, выкидывает лишнее, сжимает и отдаёт браузеру один аккуратный пакет. Без него браузер каждый раз тащит 66 файлов и 730 КБ.
- **Тесты** — это робот, который каждую ночь сам нажимает кнопки и говорит: «ты сломал отправку сообщений».
- **React/Vue** — это чужая мебель. Удобная, но её надо вносить, переучиваться и переписывать всё под неё. Нам это **не нужно**: у нас уже работает своя мебель, ей не хватает ящиков и наклеек.

**Вывод:** берём Vite + TypeScript + ESLint + тесты. Фреймворк не берём. Внешний вид и логика остаются нашими, меняется только инструмент вокруг.

## 3. Целевая архитектура

```
js/
  boot/            старт: тема, шрифты, auth-гейт, роутер (из main.js)
  core/            store (S как фасад), события, шина, время, логгер
  ui/chat/         render.js, ticks.js, search.js, ttl.js, forward.js, media.js
  ui/modals/       settings.js, people.js, group.js, profile.js, storage.js
  ui/composer/     index.js, media.js, outbox.js, scheduled.js
  backend/         supabase-клиенты, затем обёртки с типами
  crypto/          v1 + v2 (protocol уже отдельным модулем)
```

Правила, которые дают «10×»:

1. **Один файл — одна причина для изменения.** Лимит 400 строк, проверяется в CI (`scripts/check-size.mjs`).
2. **Границы модулей явные.** `ui/*` не импортирует `backend/*` напрямую — только через `core/api.js`. Тогда бэкенд можно менять и мокать.
3. **Состояние — в одном месте.** `S` остаётся, но становится фасадом над store с событиями: `store.on('message:new', ...)`. Постепенно, не одним коммитом.
4. **Рендер — точечный.** Вместо «перерисовать всё» — «обновить этот узел» (`data-mid`, `data-cid`). Полный рендер остаётся только при смене чата.
5. **Сборка — обязательная.** Деплой публикует `dist/`, а не сырые файлы; `publish-github.ps1` учится собирать.

## 4. Фазы

Каждая фаза заканчивается измеримым гейтом. Не прошли гейт — не идём дальше.

### Фаза 0 — Измерения и страховка (1–2 дня)

Без этого «в 10 раз» — это вкусовщина.

- [ ] `git init` в `C:\67` (или сделать `relik/` репозиторием), `.gitignore` (secrets, shots, dist), первый коммит, тег `v1.26.0-baseline`.
- [ ] `scripts/kpi.mjs` — собирает baseline в `kpi/baseline.json`: размер бандла, число модулей, LOC, TTI/LCP/CLS на демо, время `openChat`, кадры при скролле 10k сообщений.
- [ ] Web-vitals в телеметрию (`client_events`): `ttfb`, `lcp`, `inp`, `cls`, `ttfm` (time to first message).
- [ ] `scripts/reliability.mjs` — chaos-тест отправки (эмуляция офлайна/двойной отправки/потери ответа).
- [ ] CI: `checks.yml` + `tsc --noEmit` (пока с `checkJs: true` и мягким режимом) + `scripts/kpi.mjs --check` (бюджет не растёт).

**Гейт:** есть baseline-числа и красный/зелёный CI, который падает при ухудшении.

### Фаза 1 — Инструменты и разрез монолитов (2–3 недели)

Цель: правка перестаёт быть опасной.

- [ ] Vite: `npm run dev` (HMR) и `npm run build` → `dist/`. Дев-сервер не ломает `file://`-независимость: всё так же статика.
- [ ] TypeScript через JSDoc (`// @ts-check` в новых файлах), затем `checkJs: true` по домену `js/core`, `js/backend`.
- [ ] ESLint + Prettier, `no-restricted-globals` на `S`, правило «нет `innerHTML` без `esc`».
- [ ] Разрезать `chatView.js` на `ui/chat/*` (рендер, тики, поиск, TTL, пересылка, медиа).
- [ ] Разрезать `modals.js` и `composer.js` по фичам, `main.js` → `boot/`.
- [ ] `core/store.js` + `core/bus.js`; `S` — тонкий фасад, чтобы не переписывать 186 обращений сразу.
- [ ] Перенести `console.*` в `core/log.js` (в проде — только ошибки и метрики).
- [ ] Playwright-подобный смоук остаётся свой (`scripts/e2e.mjs`), но добавляется прогон в CI на каждый push.

**Гейт:** ни одного файла > 400 строк; `tsc` и ESLint зелёные; e2e-смоук в CI; нулевые регрессии по `TESTING.md`.

### Фаза 2 — Производительность (2–3 недели)

- [ ] Ленивая загрузка: в бандле на старте только оболочка + auth; движок чата — отдельным чанком после первого кадра.
- [ ] Виртуализация ленты: рендерим окно ± видимая область, высоты меряем, скролл якорем.
- [ ] Точечные апдейты: ✓✓, реакции, «печатает», TTL-таймеры обновляют один узел, а не всю ленту.
- [ ] `innerHTML` → шаблоны с `DocumentFragment` там, где это горячо; `content-visibility: auto` на пузырях вне экрана.
- [ ] Бюджет: boot-JS < 150 КБ gzip, CSS < 40 КБ, шрифты подмножеством.
- [ ] Service worker: precache < 300 КБ, остальное — по требованию.

**Гейт:** TTI < 1.5 с (Slow 4G, throttling 4×CPU), 10k сообщений — 60 fps при скролле, `openChat` p95 < 300 мс.

### Фаза 3 — Надёжность доставки (2–3 недели)

- [ ] Outbox 2.0: состояние `queued → sending → sent → delivered → read`, один in-flight на чат, экспоненциальный backoff с джиттером.
- [ ] Идемпотентность на сервере: уникальность `(conversation_id, client_msg_id)` — дубль физически невозможен.
- [ ] Реконсиляция при возврате связи: тянем `created_at > last_known` по каждому чату, мержим по `client_msg_id`.
- [ ] Один realtime-канал на пользователя вместо `chat:*` + `all-messages`; typing/presence — троттлинг 3 с.
- [ ] Multi-device: `device_id` в отправке, дельта-синхронизация истории и прочитанностей.
- [ ] Chaos-тест в CI: 10 000 отправок, 30% потерь, двойные ответы, рестарт вкладки → 0 потерь, 0 дублей.

**Гейт:** chaos-тест зелёный; в телеметрии `outbox_failed = 0` на 1000 реальных сообщений.

### Фаза 4 — Крипто v2 по-настоящему (3–4 недели)

- [ ] Fan-out конверта: строка на каждое устройство получателя (сейчас при `bundles.length > 1` — откат на v1).
- [ ] Прунинг устройств (не заходил 90 дней → удалить prekeys, пометить неактивным).
- [ ] Sender keys для групп (общий ключ на отправителя, ротация при изменении состава).
- [ ] Dual-read → dual-write → v1 только для чтения → выключение v1. По шагам, с откатом на каждом.
- [ ] `CRYPTO.md` переписать честно: что защищено, что нет (метаданные, PFS, AAD, sender binding).
- [ ] Верификация устройств в UI: список устройств, «отозвать», смена отпечатка — предупреждение.

**Гейт:** два устройства одного аккаунта читают 100% DM и 100% групп; отозванное устройство не читает новые сообщения; `CRYPTO_V2.enabled = true` в проде.

### Фаза 5 — Масштаб и публичный запуск (2–3 недели)

- [ ] Supabase Pro ($25/мес): бэкапы, отсутствие пауз, больше соединений.
- [ ] Индексы по `(conversation_id, created_at)`, `(user_id, updated_at)`; проверить планы запросов.
- [ ] Миграции: `supabase/migrations/` + таблица `schema_version`, применение одной командой.
- [ ] Публичный запуск: rate-limit на регистрацию/отправку, антиспам, `legal.html`/`privacy`, удаление аккаунта (уже есть), статус-страница.
- [ ] Аналитика продукта: DAU/WAU, retention D1/D7, «сколько чатов на пользователя», воронка приглашений.
- [ ] Цена: $25 Supabase + домен. Всё остальное — бесплатные тиры.

**Гейт:** 1000 DAU, p95 отправки < 400 мс, uptime 99.5% по `service_samples`.

## 6. Чего НЕ делать

- **Не переписывать на React.** Дорого, долго, ноль пользовательской пользы на этом этапе.
- **Не делать свой бэкенд.** Supabase тянет 1000 DAU; проблема не в нём, а в запросах и каналах.
- **Не добавлять TDLib/Matrix/Matrix-мост.** Другая модель продукта и другой объём работы.
- **Не включать v2 «как есть».** Сейчас это сломает второе устройство — сначала fan-out.
- **Не гнаться за фичами до Фазы 3.** Каждая новая фича в текущей архитектуре = +1 источник регрессий.
- **Не автоматизировать деплой до появления сборки.** Сначала Vite, потом `publish-github.ps1` на `dist/`.

## 8. Definition of Done для любой задачи

1. Изменение не увеличивает бюджет (`scripts/kpi.mjs --check`).
2. `node --check` / `tsc` / ESLint зелёные.
3. Есть тест: юнит для логики, смоук для UI.
4. Прогнан `scripts/e2e.mjs` на демо-режиме.
5. Обновлены `sw.js` `ASSETS` и `VER`, если добавлен ассет.
6. Обновлены RU/EN ключи (паритет проверяется в CI).
7. Задеплоено и проверено на живом URL.
8. Запись в `PLAN-10X.md` → таблица KPI (что улучшилось).

## 10. Плюсы и минусы — честно

Короткий ответ на вопрос «ничего не сломается?»: **сломаться может, и вот где именно.** Любая переделка — это риск; задача плана не «риска нет», а «риск не доходит до пользователей и откатывается за минуту».

### Плюсы

| Что даёт | Эффект |
|---|---|
| Git + гейты | работу ИИ можно откатить на любой шаг; сейчас такой страховки нет вообще |
| Типы + линтер | опечатки ловит машина, а не пользователь; ожидаемо 3–5× быстрее типовые правки |
| Разрез монолитов | правка в 2600-строчном файле → правка в 300-строчном; меньше «сломал соседнее» |
| Виртуализация + точечный рендер | открытие чата и скролл перестают лагать на телефоне |
| Outbox 2.0 + уникальность в БД | «потерялось / задвоилось» становится физически невозможным, а не «вроде нет» |
| Крипто v2 | PFS, второе устройство, отзыв устройства — реальная приватность, а не обещание |
| Миграции + индексы | публичный запуск без «а ты этот SQL прогнал?» |
| CI на каждый push | регрессия ловится до деплоя, а не через день от друга |
| Стоимость | $25/мес (Supabase Pro) + домен; остальное — бесплатные тиры |

### Минусы и риски

| Риск | Насколько больно | Как страхуемся |
|---|---|---|
| **Build-шаг (Vite)** — появляется `dist/`, править надо `publish-github.ps1`, `sw.js`, `check-assets.mjs`, CSP-хеши | среднее: забыл собрать → на сайте старое | сборка внутри publish-скрипта, версия и хеши считаются от `dist/`, проверка «живой файл содержит новую строку» |
| **Виртуализация ленты** — прыжки скролла, якоря, переход к найденному сообщению, выделение текста, Ctrl+F браузера | высокое: это самое частое место регрессий в мессенджерах | фича-флаг, старый рендер рядом, сравнение на 10k сообщений до включения |
| **Outbox 2.0 + unique-констрейнт** — в базе уже могут быть дубли | среднее: миграция упадёт | сначала дедуп-скрипт и отчёт, потом констрейнт |
| **Крипто v2** — ошибка в конверте = «недоступное сообщение» навсегда | высокое: можно потерять переписку | dual-write, флаг, откат на v1, тест «2 устройства × 3 типа чата», v1 не выключаем до 100% |
| **Разрез файлов** — 186 обращений к `S`, циклы импортов | среднее: ломается демо и звонки | по одному модулю за коммит, e2e после каждого, `S` остаётся фасадом |
| **TypeScript** — время на типизацию, соблазн закрыть всё `any` | низкое-среднее: замедление на старте | мягкий режим, `// @ts-nocheck` на переходный период, строгость только по домену |
| **Тесты и CI** — их надо поддерживать | низкое: время | только чистая логика и смоук, без фанатизма |
| **ИИ-фактор** — 20 правок в день = больше площадь регрессий | высокое | Definition of Done, коммит на каждую зелёную проверку, тег на каждый релиз |
| **Пользователи во время миграции** — возможны глюки | низкое: 5–20 знакомых, радиус мал | миграции в тихое время, откат за минуту |
| **APK/TWA, admin.html, экспорт, звонки, push** — завязаны на старые пути | среднее: их легко забыть | чек-лист «что ещё использует этот модуль» в DoD |

### Что честно НЕ станет в 10 раз лучше

- Крипто: безопасность не измеряется множителем; тут «в 10 раз» = «перестало быть дырой».
- UX: станет заметно лучше, но не в 10 раз — это вкус и итерации.
- Скорость разработки: 3–5× на типовых задачах реалистично, 10× — только на самых больных местах (правки в `chatView.js`).

### Если хочется минимум риска

Безопасный набор (почти ничего не ломает, но даёт ~2–3×, а не 10×):

1. `git init` + коммиты + откат.
2. Замеры KPI и CI-бюджет.
3. `checkJs: true` без сборки (типы через JSDoc).
4. Разрез `chatView.js`/`modals.js` на модули без смены поведения.
5. Точечный апдейт тиков (✓✓) вместо полного ререндера.
6. Тест на потерю/дубль сообщений.

**Без сборки, без смены рендера, без v2** — почти нулевой риск для пользователей. Vite, виртуализация и крипто v2 дают остальные «десятки раз», но требуют флагов и дисциплины отката.

## 12. Как резать монолиты дальше (рецепт, проверенный на TTL и прочтениях)

Порядок, который не ломает приложение:

1. Выбери **одну ответственность** (TTL, прочтения, пересылка, профиль, разметка пузыря).
2. Вынеси её состояние (`let`/`const` вверху файла) и функции в `js/ui/chat/<фича>.js`.
3. Если фиче нужны функции `chatView`, не импортируй их обратно — отдай через `bind<Фича>Hooks({...})`
   (иначе получится циклический импорт). Пример: `bindTtlHooks`, `bindReadHooks`.
4. Удали блок из `chatView.js`, добавь импорт и вызов `bind...Hooks`.
5. Добавь модуль в `sw.js` `ASSETS` и подними `VER`.
6. `node scripts/check-all.mjs` → `node scripts/build.mjs` → `node scripts/e2e.mjs --demo --url http://localhost:8100/`.
7. Опусти лимит в `scripts/check-size.mjs` до фактического размера (только вниз).
8. Покрой извлечённую чистую логику тестом в `scripts/tests/`.

Следующие кандидаты по убыванию пользы:

| Блок | Строк | Что нужно |
|---|---|---|
| разметка сообщения (`msgHtml`/`bubbleHtml`/опросы/реакции) | ~400 | передать `searchIndex`, `selectMode`, `toolsOpen` через объект состояния |
| пересылка + выбор нескольких | ~410 | вынести `selectMode`, `selectedMsgs`, `forwardMsgs`, `forwardTargets` |
| код безопасности + профиль | ~300 | `profileFp`, `FP_KEY`, `loadQrLib`; зависит от `modals` (цикла нет) |
| поиск по чату | ~120 | тесно связан с `renderMessages` — резать последним |
| `modals.js` | 1759 | по фичам: `settings`, `people`, `group`, `profile`, `storage` |
| `composer.js` | 1577 | `outbox`, `media`, `scheduled`, `polls` |
| `main.js` | 1156 | `boot/*`: тема, auth-гейт, роутер, сервис-воркер |

## 13. Что это даст на горизонте полугода

- Правки перестают быть страшными: типы, тесты, файлы по 300 строк, CI ловит регрессии.
- Сообщения не теряются и не дублируются — это проверяется машиной, а не «вроде работает».
- E2E v2 включён: PFS, несколько устройств, группы на sender keys.
- Приложение открывается за секунду и не лагает на телефоне.
- Появляется база для публичного запуска: миграции, лимиты, аналитика, стоимость под контролем.
