# Relik

> Приватный мессенджер, которому можно доверять.
> HTML + CSS Grid + Vanilla JS · E2E-шифрование · бесплатный бэкенд (Supabase)
>
> **v1.2:** закрепление и мьют чатов, контекстные меню, разделитель новых сообщений, форматирование текста и ссылки, эмодзи-пикер с категориями, drag&drop и вставка фото, управление группами, размер текста и обои, офлайн-баннер и поиск по сообщениям с навигацией.

## Быстрый демо-режим

Откройте `?demo=1` (или нажмите «Посмотреть демо без регистрации» на экране входа) — приложение запустится на локальной IndexedDB без аккаунта и сети. Демо-база отдельная (`relik-db-demo`), данные реального аккаунта не затрагиваются.

## Запуск локально

```powershell
cd C:\67\relik

# или: py -m http.server 8080 / npx serve
```

> ES-модули не работают через file:// — нужен локальный сервер.

## Как дать другу ссылку и общаться

Локальный адрес `http://localhost:8096` доступен только вам. Чтобы друг подключился, опубликуйте приложение (бесплатно):

**GitHub Pages (рекомендуется для РФ):** создайте репозиторий → «Upload files» → перетащите содержимое папки `relik` (включая `.nojekyll`) → Settings → Pages → Branch `main`, Folder `/ (root)`. Адрес: `https://username.github.io/relik/`.

**Netlify:** https://app.netlify.com → «Add new site → Deploy manually» → перетащите `relik-site-fixed.zip`. ⚠️ В РФ без VPN `*.netlify.app` замедлен до ~1–2 КБ/с — сайт будет «грузиться бесконечно».

**Firebase Hosting:** `firebase init hosting` (public dir — папка `relik`) → `firebase deploy`.

**Vercel:** `npx vercel` в папке `relik`.

**Временная ссылка без регистрации:** `npx localtunnel --port 8096` — получите публичный URL (работает, пока запущен компьютер).

После публикации:
1. Друг открывает ссылку и регистрируется.
2. Вы находите его по имени в «Новый чат» — или нажимаете **🔗 в шапке чата** и отправляете ссылку-приглашение: друг перейдёт по ней и сразу попадёт в переписку.
3. Сообщения ходят через Supabase Realtime и зашифрованы E2E.

> Ссылка-приглашение содержит id чата. Не публикуйте её в открытых местах — любой, у кого она есть, сможет войти в чат.

## Если у друга «белый экран»

1. **Раскладка определяется автоматически** — выбора «с какого вы устройства» больше нет,
   телефон/планшет/компьютер определяются по ширине окна и пересчитываются при повороте.
2. Вместо белого экрана теперь показывается тёмная заглушка «Загружаем приложение…».
   Если запуск сорвался, на ней будет **текст ошибки**, кнопка «Обновить» и ссылка
   **«Проверить, какие файлы не загрузились»** → `tools/health.html` (можно открыть напрямую:
   `https://ваш-сайт/tools/health.html`). Страница проверяет каждый файл деплоя и связь с Supabase
   и показывает статус — попросите друга прислать скриншот оттуда.
3. Частые причины на телефоне:
   - ссылка открыта **во встроенном браузере мессенджера** (Telegram/WhatsApp/VK) —
     откройте «…» → «Открыть в Chrome/Safari»;
   - очень старый браузер без поддержки ES-модулей — появится сообщение об этом;
   - мобильный интернет блокирует `*.supabase.co` — приложение покажет
     «Нет связи с сервером Relik», попробуйте Wi-Fi или VPN.
4. Приложение больше **не ждёт сеть при старте**: экран входа показывается сразу,
   сессия и чаты догружаются в фоне (раньше ожидание Supabase давало долгий пустой экран).

## Звонки: как это устроено и ограничения

- Сигналинг идёт через Supabase Realtime Broadcast: каждый слушает канал `user:<id>`,
  звонящий шлёт offer/answer/ICE в канал собеседника.
- Медиа — прямой WebRTC (P2P), STUN: Google + Twilio. TURN пока не подключён:
  в редких «строгих» NAT/корпоративных сетях звонок может не установиться.
  Для 100% надёжности нужен TURN-сервер (например, coturn на VPS или платный TURN).
- Звонки работают, когда оба пользователя онлайн в приложении.
- Звук не пишется и не хранится; звонок идёт напрямую между устройствами.
- Проверить готовность браузера: `tools/diagnostics.html` → loopback-звонок.

## Инструменты проверки

- **`tools/diagnostics.html`** — самопроверка браузера: поддержка API, живой уровень микрофона,
  реальная запись 3 сек, WebRTC loopback-звонок (полный конвейер звонка), тон 440 Гц
  и экспорт JSON-отчёта. Открывается из «Настройки → Диагностика звонков и голоса».
- **`tools/health.html`** — проверка деплоя: статус каждого файла (404 / размер / время),
  связь с Supabase, service worker, браузер. Открывается также ссылкой с экрана ошибки запуска.
- **`TESTING.md`** — QA-чеклист: голосовые, звонки, чат, группы, модалки, PWA, офлайн,
  производительность и кросс-браузер.

## Ключевые файлы для настройки

1. `supabase/schema.sql` — выполнить в SQL-редакторе проекта Supabase
2. `js/config.js` — вставить `SUPABASE.url` и `SUPABASE.anonKey`
3. `js/backend/` — Supabase клиент и API
4. `js/crypto/` — криптография (ECDH, AES-GCM)

## Инструкция по настройке Supabase

### 1. Создание проекта
1. Перейдите на https://supabase.com и создайте бесплатный проект
2. Дождитесь завершения инициализации (1-2 минуты)

### 2. Настройка базы данных
1. Откройте SQL Editor в Supabase Dashboard
2. Скопируйте и выполните содержимое `supabase/schema.sql`
3. Убедитесь, что все таблицы созданы

### 3. Настройка Storage
1. Откройте Storage в Supabase Dashboard
2. Создайте новый bucket с именем `files`
3. Сделайте bucket **private** (не public)
4. Включите RLS для bucket

### 4. Настройка Realtime
1. Откройте Database → Replication
2. Включите realtime для таблиц:
   - `messages`
   - `reactions`

### 5. Получение ключей
1. Откройте Project Settings → API
2. Скопируйте:
   - Project URL
   - anon public key
3. Вставьте их в `js/config.js`:
```javascript
export const SUPABASE = {
  url: 'https://your-project.supabase.co',
  anonKey: 'your-anon-key',
};
```

### 6. Проверка
1. Запустите локально: `.\scripts\serve.ps1`
2. Откройте http://localhost:8080
3. Зарегистрируйтесь и проверьте:
   - Auth работает
   - Профиль создаётся
   - Ключи генерируются
   - Сообщения отправляются
   - Шифрование работает (проверьте в Network tab)

## Заметка о логотипах

- Все три картинки найдены в Downloads как `.jpg` (это были JPEG) и сохранены как PNG.
- `logo-mono-org.png` (белый R) в исходнике — JPEG: JPEG не умеет прозрачность,

  нужно перегенерировать (в Elements/Figma: белый R на прозрачном фоне, PNG-24).
- Иконки 180–1024 px сгенерированы из app-иконки: они корректны для PWA (в т.ч. `maskable`).
