# Relik — план выхода в публику (P0 / P1 / P2)

Состояние на 26.10.2026. Документ дополняет `PUBLIC-READINESS.md`
(инфраструктура/юридика) и фиксирует очерёдность работ.

## 0. Уже сделано в этой итерации

- Внутренняя валюта **Relics удалена полностью**: клиент (`wallet.js`, `nft.js`,
  магазин, подарки, витрина в профиле, чип баланса), стили, переводы, картинки,
  записи в service worker. Осталась только миграция `supabase/remove_wallet.sql`
  для удаления таблиц на сервере (выполнить один раз).
- **Admin-функции убраны из приложения**: нет панели пользователей, выдачи роли,
  бейджа ADMIN, права удалять чужие сообщения и закрывать чужие опросы.
- **Аккаунт модерации сохранён**: отдельная страница `admin.html` (noindex, без
  ссылок из приложения) — жалобы, баны, журнал, ошибки клиентов. Роль в БД
  остаётся `admin`, потому что на ней завязаны RLS-политики модерации.

## 1. P0 — блокеры публичного запуска

### P0-1. Ключи и смена пароля (2–3 дня)

Проблема: `key_backup` шифруется паролем при регистрации. После сброса пароля
бэкап не перешифровывается, ошибка расшифровки глотается в `console.error`,
приватный ключ становится `null` — переписка недоступна.

Работы:
1. При успешном входе: если бэкап не расшифровался — показать диалог
   «Ключ не подошёл» с вариантами: ввести старый пароль / импортировать файл.
2. Перешифровывать `key_backup` новым паролем после сброса (нужен старый ключ
   из IndexedDB или успешная расшифровка).
3. Экспорт ключа файлом (`relik-key-<username>.json`) + импорт на новом устройстве.
4. Ротация: при смене ключа писать новый `public_key` и обновлять `group_keys`.

Критерий готовности: сброс пароля на устройстве A → вход на устройстве B →
вся история читается без «тихого» отказа.

### P0-2. Честные заявления о шифровании (0,5 дня)

`CRYPTO.md` фиксирует: нет PFS, метаданные видны, PIN — не шифрование, нет AAD.
Значит нельзя писать «как Signal». Работы:
1. Убрать/смягчить формулировки «E2E Encrypted Messenger» в шапке и `manifest`.
2. В настройках — раздел «Что защищено, а что нет» (короткий, 5 пунктов).
3. Синхронизировать `CRYPTO.md`, `README.md`, `legal.html`.

Критерий: ни одного утверждения, которое нельзя подтвердить кодом.

### P0-3. iOS и уведомления (1–2 дня)

Web Push уже реализован (`push.js`, `sw.js`, `scripts/push-service`).
Ограничение платформы: на iOS работает только в PWA, добавленном на экран.

Работы:
1. Баннер «Установить на iPhone» (Safari, не в PWA) с инструкцией.
2. Проверка push на реальном iPhone: фон/закрытая вкладка/звук/переход в чат.
3. Экран «Уведомления не работают?» с объяснением платформы.
4. Health-проверка, что VPS-рассыльщик жив (уже есть `service_status.sql`).

Критерий: сообщение от второго аккаунта даёт пуш на iPhone ≤ 15 с.

### P0-4. Юридика и данные (владелец, 1–2 недели календарно)

Из `PUBLIC-READINESS.md`: уведомление РКН, решение по локализации ПД,
контакт для обращений, правила сообщества, срок реакции на жалобу.
Плюс ежедневный `pg_dump` и проверка восстановления.

### P0-5. Бэкапы БД (0,5 дня)

Скрипт `pg_dump` на VPS + cron + удаление старше 14 дней + тестовое
восстановление на пустом проекте.

## 2. P1 — сразу после P0

1. **TTL и отложенные на сервере** (3–5 дней). Сейчас это таймеры открытой
   вкладки: `setTimeout` в `chatView.js`, `setInterval(processScheduled, 20000)`.
   Нужна Edge Function + cron: удаление просроченных и отправка отложенных
   без клиента. Плюс явная пометка в UI, что «исчезает» = «скрывается у всех,
   у кого приложение открывалось».
2. **Диагностика расшифровки** (1 день). Плашка «N сообщений не расшифровано»,
   кнопка «запросить ключ», лог без текста сообщений.
3. **Модерация как продукт** (2 дня). Правила, категории жалоб, автозакрытие,
   счётчик «жалоба принята, ответим за 72 часа».
4. **Онбординг** (2 дня). Пустой экран → «создать чат / пригласить по ссылке»,
   подсказки, экран про ключи и бэкап при первом входе.
5. **Метрики без слежки** (1 день). Счётчики регистраций/DAU/ошибок в
   `client_events` (уже есть), дашборд в `admin.html`.

## 3. P2 — после запуска

- **Capacitor** (2–3 недели): пуши, фон, App Store ($99/год), политика
  приватности, удаление аккаунта в приложении.
- **Crypto v2** (`CRYPTO_V2.enabled`): включить после двухаккаунтных тестов,
  добавить sender keys для групп.
- **Монетизация**: self-host лицензия + поддержка (B2B), платное хранилище
  медиа. Реклама невозможна технически (E2E).
- **Мультиустройство**: синхронизация group-ключей и истории между устройствами
  без пароля (device-to-device transfer по QR).
