# Relik — план до публичного запуска (решения от 26.10.2026)

Цель владельца: **репутация и гордость + заработок**. Значит сначала «до идеала»
и честная приватность, деньги — вторым шагом. Релиз в App Store/Google Play
запланирован на **2027**, до этого — только локальные APK-сборки для проверки.

Дополняет `PUBLIC-READINESS.md` (инфраструктура, юридика, бэкапы).

## 0. Сделано

- **P0-1 (ключи):** фраза из 12 слов (BIP-39) + экспорт/импорт файла ключа,
  перешифровка `key_backup` после сброса пароля, диалог восстановления вместо
  тихого `console.error`. SQL: `supabase/key_recovery.sql` (применён).
- **P0-2 (формулировки):** шапка и `phase` больше не обещают «E2E как Signal»;
  в настройках появился раздел «Что защищено, а что нет»; `CRYPTO.md` дополнен
  разделом о резервных копиях.
- **P0-4 (модерация):** `admin.html` закрыт вторым фактором — пароль панели
  (PBKDF2) + TOTP. SQL: `supabase/admin_access.sql` (применён).
- **P0-3 (оболочка):** каркас Capacitor в `mobile/` (APK-сборка на вашей машине),
  плюс `tools/phone.html` для проверки мобильной раскладки с ПК.
- **P0-5 (бэкапы):** `scripts/backup-db.sh` — ежедневный `pg_dump` с проверкой
  читаемости и ротацией 14 дней (поставить в cron на VPS).
- **P1-1 (TTL):** серверное истечение через `pg_cron` + `message_expiry`
  (`supabase/ttl_server.sql`, применён): шифротекст стирается даже при закрытом
  приложении. Отложенные отправки пока клиентские — нужен перенос шифротекста
  в `scheduled_messages` (следующий шаг).
- **P1-2 (диагностика):** плашка «не удалось расшифровать N» с кнопкой
  восстановления ключа.
- **P1-3/P1-4/P1-5:** категории жалоб + срок 72 ч в правилах; напоминание
  о бэкапе при первом входе; метрики (жалобы за 24 ч, новые за 7 дней, ошибки).
- **P1-6 (переводы):** `scripts/check-i18n.mjs` проверяет паритет RU/EN (671 ключ).
- Relics/NFT удалены из приложения **и из БД** (`remove_wallet.sql` применён).
- Admin-функции убраны из приложения; аккаунт модерации сохранён.

## 1. P0 — до того, как ссылку увидят незнакомые

### P0-1. Ключи: файл + кодовая фраза (сделано, проверено)
1. Экспорт ключа файлом `relik-key-<username>.json` + импорт на новом устройстве.
2. Кодовая фраза 12 слов (BIP39-подобный словарь, без зависимостей): из неё
   выводится ключ шифрования бэкапа, файл остаётся как резерв.
3. **Перешифровка `key_backup` при сбросе пароля** (сейчас после сброса ключ
   молча становится `null` — это главный риск потери истории).
4. Понятный диалог вместо `console.error`, если бэкап не расшифровался.

Критерий: сброс пароля на ПК → вход на телефоне → история читается.

### P0-2. Честные заявления о шифровании (сделано)
Нет PFS, метаданные видны, PIN — не шифрование. Убрать «как Signal»,
добавить экран «что защищено / что нет», синхронизировать `CRYPTO.md`,
`README.md`, `legal.html`, `manifest`.

### P0-3. APK для проверки (собирается в GitHub Actions)
1. Capacitor-проект в `mobile/`; debug APK собирается workflow `.github/workflows/android.yml`
   (Actions → Android debug APK → Artifacts → `relik-debug-apk`, ~5 МБ).
2. Проверка на живом телефоне: push, TTL, отложенные, звонки, медиа, PIN,
   поворот экрана, тёмная тема.
3. Иконка, splash, `versionCode` — чтобы APK выглядел как продукт.
4. Релиз в сторах — 2027 (P2).

### P0-4. Модерация: отдельный пароль + 2FA (сделано)
`admin.html` получает второй гейт: пароль панели (PBKDF2-хэш в приватной таблице)
+ TOTP (6 цифр, Web Crypto HMAC-SHA1, секрет в той же таблице, RLS: только admin).
Supabase-логин остаётся первым фактором.

### P0-5. Бэкапы и устойчивость (сделано 27.10.2026)
Настроено на VPS (62.113.99.46): отдельная read-only роль `relik_backup` (BYPASSRLS,
без прав записи — иначе Supabase не отдаёт схему `auth`), ежедневный `pg_dump` в 03:17,
проверка `pg_restore --list`, gzip, хранение 14 дней, лог `/var/log/relik-backup.log`.
Первый дамп: 142 КБ, 25 с. Восстановление проверять раз в квартал на пустом проекте.
Бюджет владельца — до **3 000 ₽/мес** с VPS: пока хватает Free-тарифа Supabase,
Pro ($25) включаем при первых внешних пользователях.

### P0-6. Полировка до «идеала» (выполнено в доступном объёме 27.10.2026)
Пройдено: скриншоты 11 экранов на трёх вьюпортах + автосмоук (вход, отправка,
фильтр, RU/EN, консоль) — см. UI-REVIEW.md. Светлая тема проверена скриншотом.
Осталась проверка на живых Safari iOS/Android — после установки PWA/APK.

## 2. P1 — сразу после P0

1. **TTL/отложенные на сервере** — TTL сделан: клиент пишет срок в message_expiry,
   pg_cron раз в минуту стирает шифротекст (supabase/ttl_server.sql). Отложенные тоже серверные:
   клиент шифрует сразу и кладёт в scheduled_messages, pg_cron отправляет в срок
   и ставит push в очередь (supabase/scheduled_server.sql).
2. **Диагностика расшифровки** — сделано: плашка «не удалось расшифровать N» с кнопкой восстановления ключа.
3. **Модерация как продукт** — сделано: категории жалоб, срок 72 ч в правилах, метрики в панели.
4. **Онбординг** — сделано: бэкап-напоминание плашкой снизу, «Пригласить по ссылке» на пустом экране, объяснение ключей и потерянного устройства в панели ключей, подсказка про iPhone и экран Домой.
5. **Метрики без слежки** (1 день): счётчики в `client_events`, дашборд в панели.
6. **EN-паритет** (1 день): проверка, что каждый ключ есть в `ru.js` и `en.js`,
   переключатель языка уже в настройках.

## 4. Как получать деньги (без рекламы)

Реклама технически невозможна: сервер не видит переписку, таргетинг не построить.
Продавать можно только доступ, удобство и сопровождение.

| Модель | Кому | Цена (ориентир) | Когда |
|---|---|---|---|
| **Self-host лицензия** | компании, юристы, HR, медицина | 40–150 тыс. ₽/год за инстанс + 20% за обновления | первым делом |
| **Поддержка/внедрение** | те же | 2–5 тыс. ₽/час, пакет 20 ч | вместе с лицензией |
| **Хостинг для команд (SaaS)** | малый бизнес | 250–400 ₽/мес за сотрудника | после P1 |
| **Pro для людей** | гики, журналисты | 149–299 ₽/мес: расшифрованное хранилище медиа, авто-бэкап ключей, несколько устройств | после 1000 MAU |
| **White-label** | агентства, бренды | от 300 тыс. ₽ за сборку | 2027 |
| **Донаты / Boosty** | аудитория приватности | 100–500 ₽ разово | сразу, для репутации |

Ориентиры: при расходе 3 000 ₽/мес нужен 1 контракт self-host в год или
~20 подписчиков Pro. Реалистичный порядок: репутация (open-source ядро,
статьи про E2E) → 1–2 B2B-контракта → consumer Pro.

Юридика денег: ИП/самозанятость, оферта, чеки (ЮKassa/CloudPayments для РФ),
для международных платежей — Stripe и иностранное юрлицо. Это отдельный
трек, делаем после запуска, но до первого чека.
